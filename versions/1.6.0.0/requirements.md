# 版本 1.6.0.0 需求文档

## 问题描述

### 当前问题

1. **托盘恢复页面问题**
   - 用户点击设置按钮进入设置页面
   - 点击关闭按钮最小化到托盘
   - 从托盘点击"显示窗口"恢复时，仍显示设置页面
   - 用户期望恢复时显示主界面

2. **选择模式状态问题**
   - 用户在选择模式下最小化到托盘
   - 从托盘恢复时，仍处于选择模式
   - 用户期望恢复时退出选择模式

### 问题原因

- 托盘恢复逻辑（RestoreFromTray函数）只恢复窗口显示
- 没有重置页面状态（G_CurrentPage）
- 没有重置选择模式状态（G_SelectMode）

## 修复需求

### 1. 托盘恢复时重置页面状态

**需求描述**：
从托盘恢复窗口时，自动切换到主界面。

**功能要求**：
- 恢复窗口时，将 G_CurrentPage 设置为 PAGE_MAIN
- 确保用户看到的是主界面，而不是设置或其他页面

### 2. 托盘恢复时退出选择模式

**需求描述**：
从托盘恢复窗口时，自动退出选择模式。

**功能要求**：
- 恢复窗口时，将 G_SelectMode 设置为 false
- 清空选中状态（G_SelectedItems.clear()）
- 将 G_SelectAll 设置为 false

### 3. 用户体验优化

**需求描述**：
确保用户随时可以快速访问主界面。

**功能要求**：
- 从托盘恢复后，用户可以直接看到历史记录列表
- 不需要手动返回主界面
- 保持界面状态的一致性

## 技术要求

### 1. 修改 RestoreFromTray 函数

- 在恢复窗口显示前，重置页面状态
- 在恢复窗口显示前，重置选择模式状态
- 刷新窗口显示

### 2. 测试验证

- 测试从设置页面最小化到托盘后恢复
- 测试从选择模式最小化到托盘后恢复
- 测试正常最小化到托盘后恢复

## 测试用例

### 1. 设置页面恢复测试

1. 点击设置按钮进入设置页面
2. 点击关闭按钮最小化到托盘
3. 从托盘点击"显示窗口"
4. 验证显示的是主界面，而不是设置页面

### 2. 选择模式恢复测试

1. 点击垃圾桶按钮进入选择模式
2. 选中一些记录
3. 点击关闭按钮最小化到托盘
4. 从托盘点击"显示窗口"
5. 验证显示的是主界面，且不在选择模式

### 3. 正常恢复测试

1. 在主界面点击关闭按钮最小化到托盘
2. 从托盘点击"显示窗口"
3. 验证显示的是主界面
